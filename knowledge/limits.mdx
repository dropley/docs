# Service Limits

Dropley is designed to be generous for typical use cases. These limits help ensure fair usage and system stability.

## General Limits

| Limit | Value |
|-------|-------|
| Maximum combined size of published files | 50 MB per artifact |
| Maximum files per artifact | 1,000 files |
| Maximum directory depth | 5 levels |
| Maximum path length | 255 characters |
| Supported file types | 13 extensions (see [ZIP projects](/knowledge/publishing-zip#supported-file-types)) |

The size and file-count limits apply to HTML, folder, and ZIP uploads. Add together the sizes of all files you intend to publish; the 50 MB budget is shared by the whole artifact.

For a ZIP upload, the archive itself must also fit within 50 MB. Its extracted files must fit the combined published-files budget, so an archive smaller than 50 MB can still be too large after extraction. Remove unused files or optimize large assets before trying again.

## Expiration Limits

| Duration | Available |
|----------|-----------|
| 1 day | Yes |
| 3 days | Yes (default) |
| 7 days | Yes |
| Never | No |

## Rate Limits

Publishing is rate limited to prevent abuse. The default upload allowance is **5 requests per hour per IP address**; other actions have separate limits.

If a request receives `429 Too Many Requests`, wait for the number of seconds in its `Retry-After` response header before trying again. See the [API reference](https://dropley.app/docs/api) for current API rate-limit details and response headers.

## Fair Use

- Dropley is free for everyone. Please use it reasonably.
- Automated bulk uploads or scraping are not permitted.
- Abusive usage may result in rate limit tightening or temporary blocks.

## Increasing Limits

Limits are set for system stability and cannot be increased on a per-user basis (there are no users or accounts). If your use case consistently exceeds these limits, consider self-hosting or email [hello@dropley.app](mailto:hello@dropley.app).
